# 按问题读取知识

产品0.2.0；知识库0.1.0；评分规则仍为0.1.0。知识卡是有适用边界的参考，不能擅自改动30项定义、分数或优秀门槛。

## 两种材料，分开处理

先读用户实际提供的原稿，保留情节和位置，形成自己的初步观察。原稿需要覆盖用户要求评价的范围；不能用搜索到的几场代替全稿。

知识检索只用于解决当前判断中的具体问题。先把疑问写成短语，如“人物突然改变动机”“无对白信息不清”“慢节奏没有变化”。不要把整份原稿或用户私有信息当检索query，更不要把检索结果当成该作品的事实。

## 本地检索

知识目录：`knowledge/index.json`，包含来源卡与原创教学案例的元数据。检索器只用元数据筛选，命中后按需读正文：

```text
python <skill-dir>/scripts/search_knowledge.py --query "人物突然改变动机" --mode V2 --limit 3 --include-text
```

需要精确到分项时加`--dimension V2-02`。不预先载入所有卡，也不为每个维度机械检索一轮。通常读能解释主要问题的1—3张卡，包括适用边界；需要反例时加一个相关案例即可。小问题已有足够依据时不为了形式调用检索。

`relevance`只表示词项匹配程度，不是专业正确率或评分可信度。结果为空就说明本地库没有合适命中，不强行借用不相关资料。可以调整一次同义查询或读索引标签；仍未命中时，按现有文本谨慎判断并区分知识缺口。

没有Python时直接读index.json，按mode、dimension、tags和summary选少量卡，再读取path对应文件。不要因此要求用户安装数据库或服务。

## 如何使用命中结果

1. 看来源与适用范围：一位创作者的经验不等于所有剧本的标准。电影节/开发项目的取向不等于统一评分规则。
2. 回到原稿确认：哪一处具体动作或信息支持这个解释？如果找不到，不以参考知识直接扣分。
3. 检查例外：这可能是作者有意省略、类型惯例或形式选择吗？有意选择同样需要作品效果支撑，但不强制采用某一种技法。
4. 决定建议：把知识转成针对当前情节的解释，保留作者想实现的体验；在对话中只呈现能帮助用户理解的部分。

案例卡均为原创教学示例，不是真实电影分析、专家共识或打分金标准；不得拿例子的分数给用户作品直接套分。来源卡中的“本产品用法/推论”也不冒充来源原文。

V4当前平台机制、影展截止日/资格、发行要求等动态事实，必须在用户实际需要时查对应官方来源。库内记录了查阅日期，未重新核实的资料不能用于宣称“当前规则”。不为普通剧本点评自动扩大成市场调研。

引用资料时，优先给支持当前主张的一条就近来源，不贴长书单。用户问评审依据时，解释原稿证据、参考观点与自己的判断分别是什么。不要复述知识卡的所有段落。

## 更新

来源卡应保存来源链接、查阅日期、适用边界、关联指标。新增来源或案例先核实再入库；不把用户私有剧本自动加入可分享知识库。修改知识内容更新knowledge_version；改变分项或计分尺度则另外更新rules_version，避免把知识更新误当成评分标准未变的可比复评。
